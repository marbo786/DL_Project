# ForgeryLens implementation plan

The workspace started empty. Node 24 and Python 3.10 were available. The course brief permits AI assistance for boilerplate with disclosure. The team owns model code, research decisions, experiments, interpretation and submission writing.

| Stage | Engineering work | Completion dependency |
| --- | --- | --- |
| 0 | Repository and feasibility review | Public cards and provider docs |
| 1 | Local API, independent Studio, route shell, tests | Local Python dependencies |
| 2 | Canonical manifest validation and split checks | Authorized data and verified source mapping |
| 3–7 | Research handoff and serving contracts | Team-authored models, experiments and export |
| 8–9 | Studio and evidence rendering, verified artifact reader | Validated export for real inference |
| 10–12 | Container definition, smoke tests, status and disclosure | Authorized host and artifact for public validation |

The design uses graphite surfaces, warm specimen paper and cyan interaction controls. In the Studio, a single document stage owns inspection and a narrow evidence panel holds model state. The landing visual uses the same specimen and illustrative annotation as the Studio.
